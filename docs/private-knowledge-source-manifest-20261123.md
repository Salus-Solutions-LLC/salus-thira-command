# Proposed private Knowledge source manifest

23 November 2026. Candidate for exact-revision approval and one protected execution. It has not run.

The existing consideration service evaluates the complete represented corpus but returns at most 100 candidate previews per query. The earlier approved job retained aggregate receipts. Those receipts cannot supply the full identity/version list needed for source-specific review. Replaying that consumed activation is prohibited.

This candidate reuses the existing census and consideration code with four fixed, member-neutral coordination queries. It verifies current physical source identities and versions against represented membership, creates four new scoped consideration audit receipts, and compares source/search/rights metadata before and after. Material drift, missing representation, incomplete receipts or an already consumed operation stops the run.

The export contains source identities, recorded names, current physical eTags and modified dates where available, recorded candidate original hashes and dates, representation states, and four query-match flags. Historical-only or unavailable versions remain explicit. Availability flags describe the service representation; they do not establish usable content. The existing service inspects its bounded candidate previews internally; source bodies and previews do not enter the export or logs. A global integrity binding records the in-job full representation comparison. Its underlying per-row representations are not exported and cannot be independently reconstructed from the minimized manifest.

The source list is encrypted for the local review recipient. The proposed destination is a prebound owner-only OneDrive review folder outside the ingestion corpus. Current connected-source permission readback is retained privately; the job must independently verify the exact destination and sole owner before writing, then verify the created file's bytes and permissions. It uses a create-only upload session, rejects overwrite or unknown completion, and never retries a write. No public repository artifact or source list is published. The private decryption key remains protected for the local Windows user and is not included in the repository, job, logs or cloud file.

The protected action creates one temporary job using the existing published immutable execution image and existing identity. Limits remain 0.25 CPU, 0.5 GiB, 900 seconds and zero replica retries: at most 225 CPU-seconds and 450 GiB-seconds for the process allocation, excluding other service charges. This is a resource bound, not a price quote. Four audit rows and one encrypted private file are the intended durable writes; source files, source processing/hold states, permissions, assignments and release authority remain unchanged. No application or scheduled-worker release is deployed. The reader is not activated.

The workflow uses the same pinned ARM API for both application/worker observations, verifies their selected full identity/template/configuration, removes only its correctly tagged isolated job and verifies namespace absence. It submits/starts once. Ambiguous start permits only read-only execution discovery; an unsuccessful or partial run is not replayed. GET-only retries respect bounded Retry-After responses. Upload and audit writes have no automatic retry path.

Local fictional tests cover existing-service receipt integration, source-write denial, duplicate receipt rejection, encryption and wrong-recipient/tampering bounds, private-folder sharing/binding rejection, create-only upload, exact readback failure and GET retry limits. Repository checks and Bicep validation remain required before promotion. Live identity rights, destination access, current inventory, runtime preservation and cleanup are established only by an authorized successful execution and independent private readback.

Keep decrypted corpus metadata in the restricted staff source-review collection, separate from any Member case. Determine relevance and lawful Member applicability before bringing a material source into an engagement. Original reading, contrary evidence, rights, qualified human source-use decisions, report acceptance and owner issue approval follow separately. This operation does not finish an assessment, authorize sending, resume processing or qualify every matched source.
