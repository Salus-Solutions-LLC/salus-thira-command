## Selected scanner and boundary

Use Microsoft Defender for Storage **on-upload malware scanning** on a dedicated Salus quarantine Blob account. Do not enable it across the whole subscription by default: scope the paid plan to one scanner account. Every accepted media type enters the `quarantine` container as original bytes; no Protected Member, parser, preview, report worker or ordinary evidence download can read from this account. The Event Grid topic has a system-assigned identity and may add scan-result messages only to the dedicated `scan-results` queue. The application must read that queue with its own separately scoped identity; it must not accept a caller-supplied event as proof. A result processor may copy an exact clean object to the governed evidence account only after matching tenant, blob URI, immutable version/eTag and SHA-256. A copy or transformation is a new object and must retain proof of its original and current bytes. Missing, delayed, `Malicious`, `Not Scanned`, error, timeout, size/cap, password and mismatch results remain quarantined. The queue processor is **not yet implemented** and none of these Azure resources are installed.

The scanner is a malware gate for documents, photos, scanned handwriting, diagrams, maps, geospatial containers, audio, video, archives and future accepted formats. OCR, transcription, spatial interpretation, file-type policy, rights and content accuracy are separate controls. Microsoft says Defender supports all file types up to 50 GB per blob, but encrypted and complex items can remain unscanned or time out. [Supported content and limitations](https://learn.microsoft.com/en-us/azure/defender-for-cloud/introduction-malware-scanning); [result states](https://learn.microsoft.com/en-us/azure/defender-for-cloud/understand-malware-scan-results).

## Deployment artifact

`infra/azure/defender-storage-scanner.bicep` defines one private, versioned quarantine storage account, a same-region Event Grid custom topic, a dedicated result queue, a queue-scoped **Storage Queue Data Message Sender** role for the topic identity, an identity-backed Event Grid subscription and the resource-level Defender for Storage setting. The Defender setting depends on the result subscription. It uses the stable `2025-06-01` setting API, disables sensitive-data discovery, sends results to Event Grid, avoids blob index tags as an authorization source, declares no file-type exclusions and requires an explicit monthly GB cap. The queue processor still needs a separately scoped queue-reader/blob-reader/evidence-writer identity, exact-object validation, idempotent retries and stale/missing-result reconciliation. Deploy only through the governed Azure identity after that processor, cost and isolated storage permissions are reviewed. An unused queue or scanner does not satisfy the Member intake release gate. [Microsoft Bicep resource reference](https://learn.microsoft.com/en-us/azure/templates/microsoft.security/2025-06-01/defenderforstoragesettings); [Event Grid identity delivery](https://learn.microsoft.com/en-us/azure/event-grid/deliver-events-using-managed-identity); [Event Grid setup](https://learn.microsoft.com/en-us/azure/defender-for-cloud/defender-for-storage-configure-malware-scan).
