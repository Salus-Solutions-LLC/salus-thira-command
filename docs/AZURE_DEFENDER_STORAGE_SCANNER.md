## Selected scanner and boundary

Use Microsoft Defender for Storage **on-upload malware scanning** on a dedicated Salus quarantine Blob account. Do not enable it across the whole subscription by default: scope the paid plan to one scanner account. Every accepted media type enters the `quarantine` container as original bytes; no Protected Member, parser, preview, report worker or ordinary evidence download can read from this account. The Event Grid topic has a system-assigned identity and may add scan-result messages only to the dedicated `scan-results` queue. The application must read that queue with its own separately scoped identity; it must not accept a caller-supplied event as proof. A result processor may copy an exact clean object to the governed evidence account only after matching tenant, blob URI, immutable version/eTag and SHA-256. A copy or transformation is a new object and must retain proof of its original and current bytes. Missing, delayed, `Malicious`, `Not Scanned`, error, timeout, size/cap, password and mismatch results remain quarantined. The queue processor is **not yet implemented** and none of these Azure resources are installed.

The scanner is a malware gate for documents, photos, scanned handwriting, diagrams, maps, geospatial containers, audio, video, archives and future accepted formats. OCR, transcription, spatial interpretation, file-type policy, rights and content accuracy are separate controls. Microsoft says Defender supports all file types up to 50 GB per blob, but encrypted and complex items can remain unscanned or time out. [Supported content and limitations](https://learn.microsoft.com/en-us/azure/defender-for-cloud/introduction-malware-scanning); [result states](https://learn.microsoft.com/en-us/azure/defender-for-cloud/understand-malware-scan-results).

`salus_scan_quarantine.py` is a source-only staging/read component for the existing 25 MB path. It uses managed identity and no overwrite, requires a Blob version and ETag, and re-reads the named version with a bounded download and SHA-256 check. The web upload selects the existing runtime identity; only the result worker selects the dedicated quarantine-reader identity. `salus_scan_results.py` qualifies a trusted-queue result against those bytes. The draft intake route has a nonproduction `SALUS_PACKAGE_SCAN_MODE=defender` branch that stages a file and returns `Pending` without adding it to clean evidence; the default inline scanner path remains unchanged. `salus_scan_worker.py` contains a bounded managed-identity queue poll and acknowledgement rule. The draft processor serializes the pending record, checks exact scope and result, re-reads the named blob version, verifies a clean evidence copy and records promotion; adverse outcomes stay held, while a contrary later result suspends the evidence. A 24-hour missing-result reconciliation moves stale originals to a manual hold; a late result cannot automatically release them. These are **source candidates, not an operating scanner**: the scheduled job, identity grants, Event Grid delivery, cost and recovery remain untested in Azure. [Blob client version and download API](https://learn.microsoft.com/en-us/python/api/azure-storage-blob/azure.storage.blob.blobclient); [container version-specific client API](https://learn.microsoft.com/en-us/python/api/azure-storage-blob/azure.storage.blob.containerclient).

The draft `package_intake_pending_scans` table retains tenant, assessment, quote, request, uploader, Blob URI/name/version/ETag, digest, size, hold and retention metadata. Portable backups include this metadata but **never include unscanned original bytes**. Recovery validation reports an external quarantine dependency whenever a record is not promoted; restore changes `Pending` to `Reconcile` so an old result cannot unlock it. Before operational release, prove that the isolated Azure quarantine account retains and can recover each named version under the agreed retention and legal-hold policy, or document a controlled resubmission path. A database backup alone is not complete disaster recovery for held originals.

## Deployment artifact

`infra/azure/defender-storage-scanner.bicep` defines one private, versioned quarantine storage account, a same-region Event Grid custom topic, a dedicated result queue, a queue-scoped **Storage Queue Data Message Sender** role for the topic identity, an identity-backed Event Grid subscription and the resource-level Defender for Storage setting. It also defines a custom Blob-write role for the web identity and scoped Blob-read/queue-process roles for the worker identity. The web code uses a unique name and `overwrite=False`; the role itself permits Blob write, so live tests must prove creation, blocked read/list/delete and no overwrite through the web path. Creating the role requires `Microsoft.Authorization/roleDefinitions/write`, which the Contributor sign-in lacks; the existing subscription Owner identity is the scoped administrative route if Marc signs in with that account. The worker is a scheduled Container Apps Job using an immutable reviewed image digest. Its five-minute schedule starts at most 288 idle executions daily; each execution is bounded to 60 seconds. Measure queue latency, duration, failed executions and cost before deployment, then tune the interval or adopt a tested event trigger. A stale-result sweep still needs reliable execution when the queue is empty. The Defender setting depends on the installed job and result subscription. It uses the stable `2025-06-01` setting API, disables sensitive-data discovery, sends results to Event Grid, avoids blob index tags as an authorization source, declares no file-type exclusions and requires an explicit monthly GB cap. Deploy only through the governed Azure identity after cost and isolated storage permissions are reviewed. An unused queue or scanner does not satisfy the Member intake release gate. [Microsoft Bicep resource reference](https://learn.microsoft.com/en-us/azure/templates/microsoft.security/2025-06-01/defenderforstoragesettings); [Event Grid identity delivery](https://learn.microsoft.com/en-us/azure/event-grid/deliver-events-using-managed-identity); [Event Grid setup](https://learn.microsoft.com/en-us/azure/defender-for-cloud/defender-for-storage-configure-malware-scan); [custom roles](https://learn.microsoft.com/en-us/azure/role-based-access-control/custom-roles); [Put Blob permission](https://learn.microsoft.com/en-us/rest/api/storageservices/put-blob).
