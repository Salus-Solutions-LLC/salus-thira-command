# Protection Advisor Level 1 intake and evidence request — proposed revision

**Status:** Proposed implementation of SAL-D049; no production change or Protected Member release.  
**Owner:** Salus Solutions. **Handling:** Salus Internal Confidential. **Prepared:** 27 September 2026.  
**Authority:** SALUS_PROGRAM_CHARTER.md; SALUS_DECISION_REGISTER.md; SALUS_THREE_LEVEL_SERVICE_FRAMEWORK.md; SALUS_SALINTEL_SALTHIRA_METHOD_STANDARD.md; SALUS_SALOPS_METHOD_REPORT_STANDARD.md; SALUS_SALCAPA_INTEGRATED_REPORT_STANDARD.md; approved Protection Advisor example report.

## Purpose and boundary

Protection Advisor Part 1 stays anonymous and short enough to finish. Part 2 stays authenticated and asks only for details the respondent already knows. The full Level 1 evidence request follows a voluntary scope discussion and authorized agreement; it is not an upload requirement or a condition of viewing preliminary results. Salus records unavailable evidence as an unknown. The minimum start gate is a qualified sponsor, covered entity and assessment boundary, source permissions, handling route, an urgent-concern screen, and commercial authorization.

The Level 1 request supports a bounded SalINTEL™ baseline, all six SalTHIRA™ steps at provisional Level 1 depth across the five mission areas and applicable 32 core and sector capabilities, Level 1 SalOPS™ options, and a SalCAPA™ decision summary after component approval. It does not front-load Level 2 interviews, fieldwork, tests, or sensitive person-level records.

## Part 1 proposed change

Do not add a required question or a file upload. Keep existing response choices, including uncertainty and decline. After the preliminary result, explain: “Your answers identify preliminary strengths, concerns and information gaps. A Level 1 Initial Pass can review existing information, set provisional priorities and show which questions would justify a later Level 2 assessment.” Offer separate voluntary paths to discuss Level 1 and a specific additional service. Severity or service-depth signals must not be mistaken for an authorized first Level 2 or Level 3 purchase.

## Part 2 proposed change

Preserve existing required profile fields. Add one optional availability question, without file upload:

> Which existing materials could your organization make available after a Level 1 scope and secure transfer method are agreed? Select any that apply: plans; leadership and roles; incident or exercise records; general facility and dependency information; permit, inspection or insurance summaries; vendor or responder arrangements; other; none known; not sure; prefer to discuss.

Store availability only in the correct engagement with a save/reload path. Do not use a free-text field for sensitive details. If safe persistence is not available, ask this after submission in a secure, governed follow-up rather than presenting an unsaved question as submitted.

## Protected Member request after Level 1 commitment

| Timing | Minimum information or existing record category | Why it matters |
|---|---|---|
| Start gate | Authorized sponsor/contact, decision role, covered entity/site/operation, general location, scope exclusions, purpose, urgent concern, permissions and handling | SalCAPA™ engagement boundary and safe collection; SalINTEL™ source boundary |
| If existing | Organization chart, board/management authority, succession, personnel/volunteer/contractor roles in aggregate | SalINTEL™ governance and trusted access; SalTHIRA™ capability owner; SalOPS™ task authority |
| If existing | Emergency, security, crisis communications, evacuation, shelter, continuity and recovery plans | SalINTEL™ plan currency; SalTHIRA™ targets and current capability; SalOPS™ practical options |
| If existing | Essential functions, failure thresholds, restoration priorities and general facility/utility/water/communications/technology/transport dependencies | SalINTEL™ eight dimensions; SalTHIRA™ scenarios, consequences, gaps and recovery timing; SalOPS™ resource sequence |
| If existing | Prior risk studies, incident/near-miss summaries, exercises, inspections, maintenance, corrective actions | Actual performance versus plans; confidence and contradiction checks |
| If existing | Responder, mutual-aid, vendor and supply arrangements; relevant resource inventories | Competing-demand and feasibility analysis |
| If existing | Permit/inspection index, insurance coverage/loss summary, relevant contractual duties, preparedness funding constraints | Dedicated compliance screen; cost, legal and resource feasibility |
| If applicable | Animal care/disease, aviation, hazardous material, public-event and other sector records | Sector capability and hazard screen |

An inventory or title list is sufficient initially. Salus requests individual files only when relevant to agreed Level 1 scope and approved secure handling. No blanket directory or bulk-upload requirement.

## Restricted collection

Do not collect resident or employee directories, individual medical or background files, gate codes, passwords, detailed tactical or security layouts, account data, or person-specific insider-risk material in Part 1 or Part 2. If such evidence is needed later, document lawful purpose, minimum fields, recipients, restrictions, secure transfer, separate storage, review and retention within the Protected Member boundary. No cross-engagement disclosure follows from enterprise learning.

## Current-version reconciliation

The currently approved example Protection Advisor report recommends a Level 3 engagement as the lead first purchase. The current public implementation also displays service-specific levels in recommendations. Those statements need controlled reconciliation with SAL-D032 and SAL-D048: the first integrated assessment offer is Level 1; higher levels can be described only as later conditional options. The approved example remains the visual and content authority where compatible with later governing decisions. Review the exact live report version and all PDF, DOCX, print and on-screen paths; do not create a duplicate governed report.

## Acceptance criteria before release

1. Part 1 remains anonymous, has no added required question/upload, and reaches a Level 1 first offer without implying measured risk or compliance.
2. Part 2 optional availability answer persists and reloads in the correct member/engagement, or is moved to a governed post-submission step.
3. A respondent may finish with “not sure” or no existing records; absence is not misreported as a violation or failed capability.
4. Member-facing list separates start gates from useful existing records and excludes unnecessary PII.
5. Level 1 first and conditional Level 2/3 language agree across UI, preliminary result, report executive summary, recommendations, PDF, DOCX and print.
6. Service discovery is evidence-linked and optional; site names are checked against current public service pages, while capacity/licensing/pricing are separately verified.
7. Analyst/human review, confidentiality, report identity/version, accessibility, rendered-page, rollback and SAL-D027 impact gates pass before promotion.
